NetWatch — Network Device Connectivity Monitor

A Python-based network monitoring application that demonstrates core Computer Networks concepts including IP addressing, ICMP/ping, network latency, client-server architecture, and real-time connectivity monitoring. Built for a Computer Engineering academic project.

Python 3.12 Flask 3 SQLite Chart.js

Computer Networks Concepts Demonstrated

📡 IP Addressing

Both IPv4 and IPv6 addresses are accepted. Python's ipaddress module validates addresses before storage.

🏓 ICMP & Ping

Connectivity is verified using the system ping command which sends ICMP Echo Request packets and awaits Echo Reply.

⏱️ Network Latency

Round-trip time (RTT) is measured in milliseconds for each probe. Trends are graphed over time.

📦 Packet Loss

Packet loss percentage is computed from the ratio of failed probes to total probes over a selected time window.

🖥️ Client-Server

Flask implements a REST API server. The browser acts as the client, fetching JSON data and rendering dashboards.

🌐 DNS Resolution

Hostnames are accepted as monitoring targets. The OS resolves them to IP addresses when executing the ping command.

🔧 Network Troubleshooting

Manual connectivity tests, event logs, error classification, and status history aid in diagnosing network issues.

📊 Availability Metrics

Availability (%) = Successful Probes ÷ Total Probes × 100. Calculated from real stored measurements.

Known Limitations

  • ICMP Filtering: Many devices block ICMP Echo requests at the firewall. A failed ping does not necessarily mean the device is off.
  • OS Permissions: Some OS configurations may restrict raw ICMP operations or require elevated privileges.
  • Probe-Based Availability: Availability is estimated from probes and may not reflect true service uptime between checks.
  • Local Scope: This application is intended for authorized monitoring of explicitly registered targets only.
  • No Subnet Discovery: The application does not scan IP ranges or discover devices automatically.
  • Topology is Logical: Physical network connections are not auto-discovered. The topology view is illustrative only.
  • Single-Host Deployment: This is a single-machine application — no distributed monitoring.

How Monitoring Works

  1. On startup, a background scheduler thread begins checking all enabled devices.
  2. Each device has a configurable monitoring interval (5–300 seconds).
  3. When a device is due, a worker thread is dispatched (bounded by max concurrency).
  4. The worker calls ping_service.ping() which runs the OS ping command via subprocess.run() with shell=False.
  5. The command output is parsed for round-trip time. The return code determines reachability.
  6. Results are stored in the probe_results table with a UTC timestamp.
  7. If the device status changed, an event is logged in the events table.
  8. The dashboard polls /api/dashboard every 5 seconds and updates without triggering new pings.
